# 父子分块策略

## 📋 概述

父子分块是一种智能文档切块策略，将文档分为**父块**和**子块**两层结构，兼顾检索精度和上下文完整性。

---

## 🎯 设计原理

### 传统分块的问题

```
传统分块：
┌────────┐ ┌────────┐ ┌────────┐
│ 块 1   │ │ 块 2   │ │ 块 3   │
│ 500字  │ │ 500字  │ │ 500字  │
└────────┘ └────────┘ └────────┘

问题：
- 块太小 → 缺少上下文，LLM 难以理解
- 块太大 → 检索精度下降
```

### 父子分块解决方案

```
父子分块：

父块 (Parent Chunk) - 2000 字符
┌─────────────────────────────────────────────┐
│                                             │
│  子块1 (500字)  子块2 (500字)  子块3 (500字) │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
│  │ 向量检索 │  │ 向量检索 │  │ 向量检索 │  │
│  └──────────┘  └──────────┘  └──────────┘  │
│                                             │
└─────────────────────────────────────────────┘
          ↑
    返回给 LLM 的是父块（上下文完整）
```

---

## 🔄 检索流程

```
1. 用户提问："什么是 RAG？"
        │
        ▼
2. 将问题向量化
        │
        ▼
3. 在 Milvus 中检索子块
   → 匹配到"子块 15"
        │
        ▼
4. 映射到父块
   → "子块 15" 属于"父块 5"
        │
        ▼
5. 返回父块给 LLM
   → LLM 获得完整上下文
```

---

## ⚙️ 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| chunk_size | 500 | 子块大小（字符数） |
| chunk_overlap | 50 | 子块重叠大小 |
| parent_chunk_size | 2000 | 父块大小（字符数） |

### 配置建议

| 场景 | chunk_size | parent_chunk_size |
|------|------------|-------------------|
| 通用文档 | 500 | 2000 |
| 技术文档 | 300 | 1500 |
| 长篇文章 | 800 | 3000 |
