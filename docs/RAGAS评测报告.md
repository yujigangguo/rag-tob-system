## 1. 总体结论

| 指标 | 得分 | 评级 |
|---|---|---|
| **Faithfulness(忠实度)** | **1.0000** | 🟢 回答完全有据可依,零编造 |
| **Answer Relevancy(答案相关性)** | **0.7990** | 🟡 良好,个别回答偏简短 |
| **Context Precision(上下文精确率)** | **1.0000** | 🟢 检索结果全部相关且排前 |
| **Context Recall(上下文召回率)** | **1.0000** | 🟢 标准答案要点全部被上下文覆盖 |
| **Answer Correctness(答案正确性)** | **0.8541** | 🟢 良好,少数回答遗漏次要条款 |
| **平均分** | **0.9306** | 🟢 整体优秀 |

**一句话结论**:检索链路(向量 + BM25 + RRF + 父子分块)表现优秀,三指标满分;生成链路忠实不编造,主要扣分点是部分回答"要点覆盖不全"(漏掉标准答案中的次要条款)与个别回答过于简短影响相关性评分——属生成质量问题,可通过提示词优化提升,不涉及检索架构改动。

## 2. 评测方法

1. 自动创建评测知识库,上传《员工手册》《产品说明-星云智能音箱》《常见问题 FAQ》三份文档并解析入库;
2. 每题走真实链路:问题 → embedding → Milvus 向量召回 + BM25 关键词召回 → RRF 融合 → 子块映射回父块(取前 5 段)作为上下文;
3. 用与线上一致的提示词调用 qwen-max 生成回答;
4. RAGAS 用 qwen-max 作为 judge LLM、通义 embedding 计算语义相似度,输出 5 项指标。

## 4. 亮点分析

1. **零编造(Faithfulness 1.0)**:系统提示词"只依据资料作答 + 资料不足时明确拒答"约束有效,16 条回答全部忠实于检索上下文;
2. **检索质量优秀(Precision / Recall 均 1.0)**:16 个问题的相关上下文全部命中且排在前列——混合检索(RRF 融合向量 + BM25)+ 父子分块(子块检索、父块作上下文)设计有效;
3. **数值类问题表现稳定**:售价、年假天数、倍数、时限类问题 Correctness ≥ 0.93。

## 5. 薄弱项分析与改进建议

### 5.1 Answer Correctness(0.8541)— 主要扣分点:回答漏掉标准答案的次要条款

典型例子:

| 问题 | 系统回答(截取) | 标准答案 | 差距 |
|---|---|---|---|
| 音箱无法连接 Wi-Fi 时怎么处理? | 确认路由器支持 2.4GHz 频段;将音箱靠近路由器后重试 | 确认 2.4GHz 频段,**并靠近音箱后重试** | 措辞细节差异(0.52) |
| 法定节假日加班怎么算? | 按 3 倍工资计算 | 按 3 倍工资计算,**且加班须提前在 OA 申请并经主管审批** | 遗漏 OA 申请条款(0.59) |
| 正式员工离职提前多久? | 提前 30 天书面通知 | 提前 30 天书面通知,**并完成工作交接和资产归还** | 遗漏交接条款(0.61) |

**结论**:检索上下文其实已包含这些条款(Context Recall = 1.0),是生成环节没有展开——回答"够用但不够全"。

**改进建议**:
- 提示词中强调"完整覆盖资料中的全部相关要点,不要只回答核心结论"(在 `app/rag/prompts.py` 的 RAG_SYSTEM_PROMPT 增加"要点完整"约束);
- 适当增大 `final_top_k`(5 → 7)或父块大小,给生成更充分的上下文。

### 5.2 Answer Relevancy(0.799)— 次要扣分点:回答过于简短

"会议室怎么预订"(0.622)、"VPN 怎么开通"(0.734)、"离职提前多久"(0.743)等流程类问题,回答只有 1~2 行,judge 判定信息量不足。

**改进建议**:同一提示词优化即可——要求"先给结论,再补充前提条件/操作步骤",并保留 [1] 来源标注。

### 5.3 复测口径说明

- Answer Correctness 由"事实一致性 + 语义相似度"加权(各 0.5),对措辞敏感;
- 若后续调整提示词/参数,建议**重跑同一评测集**对比分数,保证可比性。
