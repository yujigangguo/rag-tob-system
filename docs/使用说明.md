# 企业内容知识问答系统 · 使用说明

> 本文档汇总系统的连接信息、账号密码、配置项与启动方式,便于部署和排查问题。

## 一、核心连接信息速查表

### 1. MySQL

| 项 | 值 |
|----|-----|
| 地址(宿主机) | `127.0.0.1:3306` |
| 地址(容器内) | `mysql:3306`(Docker 部署时后端使用) |
| 数据库名 | `rag_db` |
| 应用账号 | `rag_user` |
| 应用密码 | `rag_pass123` |
| root 账号 | `root` |
| root 密码 | `root123456` |
| 测试数据库 | `rag_db_test`(pytest 自动创建) |

命令行连接示例:

```bash
# 应用账号
mysql -h 127.0.0.1 -P 3306 -u rag_user -prag_pass123 rag_db

# root 账号
mysql -h 127.0.0.1 -P 3306 -u root -proot123456
```

**Navicat 连接步骤:**

1. 打开 Navicat → 左上角「连接」→ 选择「MySQL」。
2. 在「常规」标签页填写:

| 字段 | 填什么 |
|------|--------|
| 连接名 | 随意,如 `rag` |
| 主机 | `127.0.0.1` |
| 端口 | `3306` |
| 用户名 | `rag_user`(或 `root`) |
| 密码 | `rag_pass123`(root 则 `root123456`) |

3. 点左下角「测试连接」,提示"连接成功"后点「确定」。

连接后可看到数据库 `rag_db`,内含 6 张表:`users`、`knowledge_bases`、`documents`、`chunks`、`chat_sessions`、`chat_messages`。

> 若报 "Authentication plugin 'caching_sha2_password' cannot be loaded":本项目 MySQL 已强制使用 `mysql_native_password` 认证,正常不会出现;若仍遇到,将 Navicat 升级到 12 以上版本即可。

### 2. Milvus 向量库

| 项 | 值 |
|----|-----|
| 地址 | `http://localhost:19530`(compose 容器内用 `milvus:19530`) |
| 版本 | 2.4.4 |
| 集合命名 | 每个知识库一个集合,命名 `kb_{知识库ID}` |
| 数据卷目录 | `E:/milvus_redis/volumes`(`.env` 的 `MILVUS_VOLUME_DIR`) |

Milvus 由以下组件组成,**均已纳入 `docker-compose.yml` 统一管理**:

| 组件 | 镜像 | 说明 |

| milvus-standalone | milvusdb/milvus:v2.4.4 | 主服务,端口 19530(gRPC)/ 9091(监控) |
| milvus-etcd | quay.io/coreos/etcd:v3.5.5 | 元数据存储 |
| milvus-minio | minio/minio:RELEASE.2023-03-20 | 对象存储,账号 `minioadmin` / `minioadmin` |
| milvus-redis | redis:latest | 缓存,端口 6379,密码 `1234` |

## 二、默认账号

系统**不内置默认账号**,需通过注册页自行注册。

- 冒烟测试曾在开发库创建过:`testuser` / `test123456`(仅限本机测试残留,可忽略)
- 密码规则:至少 6 位;采用 bcrypt 哈希存储,不可逆

## 三、环境配置(.env)

`.env` 位于项目根目录,复制 `.env.example` 后填写。关键项:

| 配置项 | 说明 | 默认值 |
|--------|------|--------|
| `SECRET_KEY` | JWT 签名密钥,**生产务必修改** | `change-me-in-production-please` |
| `LLM_API_KEY` | 通义 API Key(qwen-max 生成,必填) | 空 |
| `LLM_MODEL` | 大模型 | `qwen-max` |
| `EMBEDDING_API_KEY` | 通义 embedding Key(可与 LLM 相同) | 空 |
| `DB_HOST` / `DB_PORT` | MySQL 地址 | `127.0.0.1` / `3306` |
| `DB_USER` / `DB_PASSWORD` | MySQL 账号 | `rag_user` / `rag_pass123` |
| `DB_NAME` | MySQL 库名 | `rag_db` |
| `MILVUS_URI` | 向量库地址 | `http://localhost:19530` |
| `DEFAULT_HISTORY_ROUNDS` | 默认历史对话轮数 | `5` |
| `CAPTCHA_ENABLED` | 图形验证码开关(测试可关) | `true` |
| `LOG_LEVEL` | 日志级别(DEBUG/INFO/WARNING/ERROR) | `INFO` |

## 四、启动方式

### 方式 A:本地开发(前后端分离)

```bash
# 1. 起基础设施(MySQL + Milvus)
docker compose up -d mysql milvus

# 2. 启动后端(端口 8000)
uv sync
uv run uvicorn app.main:app --reload --port 8000

# 3. 启动前端(端口 5173,已代理 /api 到后端)
cd frontend
npm install
npm run dev
```

### 方式 B:Docker 一键部署

```bash
# 先填好 .env 的 LLM_API_KEY / EMBEDDING_API_KEY
docker compose up -d --build
```

- 前端:`http://localhost:8080`
- 后端文档:`http://localhost:8000/docs`

```bash
docker compose down        # 停止
docker compose down -v     # 停止并清空 MySQL 数据(慎用)
```

## 七、日志

- 日志文件:`data/logs/app.log`(按 10MB 轮转,保留 5 份)
- 同时输出到控制台,格式:`时间 | 级别 | 模块 | 消息`
- 日志级别由 `.env` 的 `LOG_LEVEL` 控制(默认 `INFO`,排查问题可设 `DEBUG`)

已记录的关键事件:用户注册/登录、知识库创建/删除、文档上传/解析(成功与失败)、问答检索与生成、检索失败告警。

此外每个 HTTP 请求都会记录方法、路径、状态码与耗时(如 `GET /api/auth/captcha -> 200 (74.62ms)`),`/health` 已跳过避免刷屏。

```bash
# 实时查看后端日志
tail -f data/logs/app.log

# Docker 部署时查看后端日志
docker logs -f rag-backend
```

## 八、常见问题排查

| 问题 | 排查方向 |
|------|---------|
| 后端启动报 MySQL 连接失败 | 确认 `docker compose up -d mysql` 已启动;核对 `.env` 的 DB_* 配置 |
| 注册/登录报"验证码错误" | 确认验证码输入正确、未过期(5 分钟);测试环境可设 `CAPTCHA_ENABLED=false` |
| 文档上传解析失败 | 检查 `EMBEDDING_API_KEY` 是否有效;看文档 `status` 字段的 `error_msg` |
| 上传文档一直卡住 | Docker 部署时后端连 Milvus 应用 `milvus:19530`(服务名),不是 `localhost`;并确认 milvus 容器与 backend 在同一 Docker 网络 |
| 问答无输出 | 检查 `LLM_API_KEY` 是否已填;看后端日志 |
| 检索不到内容 | 确认知识库已上传文档且状态为 `completed`;用 `eval.py` 评估召回率 |
| 前端请求 401 | token 过期,重新登录;检查 localStorage 是否存有 token |
| Docker 后端连不上 Milvus | 确认 milvus 容器在运行,且已接入 backend 的网络(见"上传卡住"条目) |
| 忘记 MySQL 密码 | 见第一节表格;或 `docker exec -it rag-mysql mysql -uroot -proot123456` |

## 九、安全提示

1. **生产环境务必修改所有默认密码与密钥**(以下均出现在 `docker-compose.yml` 中,推送 GitHub 后会公开):
   - `SECRET_KEY`(JWT 签名密钥,默认 `change-me-in-production-please`)
   - MySQL:`root123456` / `rag_pass123`
   - MinIO:`minioadmin` / `minioadmin`
   - Redis:`1234`
2. `.env` 已被 `.gitignore` 排除,**真实 API Key 不会被提交**;但推送到 GitHub 前请确认 `git status` 里没有 `.env`。
3. 验证码生产环境保持 `CAPTCHA_ENABLED=true`。
