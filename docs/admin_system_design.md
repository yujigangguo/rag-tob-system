# 后台管理系统设计文档

## 1. 项目概述

### 1.1 背景
基于现有的 FastAPI RAG 系统，需要开发一个后台管理系统，用于管理用户权限和系统配置。

### 1.2 核心需求
- 第一个注册用户自动成为超级管理员
- 完整的用户管理功能（查看、编辑、禁用、删除）
- 灵活的角色分配（超级管理员、部门管理员、员工）
- 部门管理功能（创建、编辑、删除部门）
- 权限管理功能（查看角色权限配置）

### 1.3 技术栈
- **后端**: FastAPI + SQLAlchemy + SQLite/PostgreSQL
- **前端**: Vue 3 + Vite + Element Plus + Pinia + Vue Router
- **权限模型**: RBAC（基于角色的访问控制）

## 3. 功能设计

### 3.1 用户管理功能

#### 3.1.1 用户列表
- 分页显示所有用户
- 支持按用户名、角色、部门搜索和筛选
- 显示用户基本信息：ID、用户名、角色、部门、创建时间、状态

#### 3.1.2 用户操作
- **查看详情**: 显示用户完整信息
- **编辑用户**: 修改用户名、角色、部门
- **分配角色**: 设置用户角色（super_admin, dept_admin, employee）
- **分配部门**: 将用户分配到指定部门
- **禁用/启用**: 控制用户账户状态
- **删除用户**: 删除用户账户（需二次确认）

#### 3.1.3 第一个用户自动超级管理员
- 注册时检查用户表是否为空
- 如果是第一个用户，自动设置角色为 `super_admin`
- 后续用户默认角色为 `employee`

### 3.2 部门管理功能

#### 3.2.1 部门列表
- 显示所有部门
- 显示部门下的用户数量
- 支持创建、编辑、删除操作

#### 3.2.2 部门操作
- **创建部门**: 输入部门名称，创建新部门
- **编辑部门**: 修改部门名称
- **删除部门**: 删除部门（需检查是否有用户关联）

### 3.3 权限管理功能

#### 3.3.1 角色权限配置
- 查看系统角色列表
- 查看每个角色的权限配置
- 权限矩阵展示

#### 3.3.2 权限说明
- **super_admin**: 系统管理员，拥有所有权限
- **dept_admin**: 部门管理员，管理本部门用户和知识库
- **employee**: 普通员工，只能查看本部门知识库

## 4. API 设计

### 4.1 管理后台 API

#### 4.1.1 用户管理
```
GET    /api/admin/users              # 获取用户列表（分页、搜索）
GET    /api/admin/users/{id}         # 获取用户详情
PUT    /api/admin/users/{id}         # 更新用户信息
DELETE /api/admin/users/{id}         # 删除用户
PUT    /api/admin/users/{id}/role    # 分配用户角色
PUT    /api/admin/users/{id}/department  # 分配用户部门
PUT    /api/admin/users/{id}/status  # 禁用/启用用户
```

#### 4.1.2 部门管理
```
GET    /api/admin/departments        # 获取部门列表
POST   /api/admin/departments        # 创建部门
PUT    /api/admin/departments/{id}   # 更新部门
DELETE /api/admin/departments/{id}   # 删除部门
```

#### 4.1.3 权限管理
```
GET    /api/admin/roles              # 获取角色列表
GET    /api/admin/permissions        # 获取权限配置
```

### 4.2 请求/响应格式

#### 用户列表请求
```json
GET /api/admin/users?page=1&page_size=10&search=test&role=employee&department_id=1
```

#### 用户列表响应
```json
{
  "items": [
    {
      "id": 1,
      "username": "admin",
      "role": "super_admin",
      "department_id": null,
      "department_name": null,
      "is_active": true,
      "created_at": "2024-01-01T00:00:00"
    }
  ],
  "total": 100,
  "page": 1,
  "page_size": 10
}
```

#### 角色分配请求
```json
PUT /api/admin/users/1/role
{
  "role": "dept_admin"
}
```

## 5. 前端设计

### 5.1 页面布局

#### 管理后台布局
- **侧边栏**: 导航菜单（用户管理、部门管理、权限管理）
- **顶部栏**: 用户信息、退出登录
- **内容区域**: 动态加载子页面

#### 用户管理页面
- **搜索栏**: 用户名搜索、角色筛选、部门筛选
- **操作栏**: 添加用户按钮
- **表格**: 用户列表，包含操作列（查看、编辑、分配角色、分配部门、禁用、删除）
- **分页**: 底部分页组件

#### 部门管理页面
- **操作栏**: 添加部门按钮
- **表格**: 部门列表，包含操作列（编辑、删除）
- **弹窗**: 创建/编辑部门表单

### 5.2 交互设计

#### 用户操作流程
1. 点击"分配角色"按钮 → 弹出角色选择对话框 → 选择角色 → 确认
2. 点击"分配部门"按钮 → 弹出部门选择对话框 → 选择部门 → 确认
3. 点击"禁用"按钮 → 二次确认 → 执行禁用操作
4. 点击"删除"按钮 → 二次确认 → 执行删除操作

#### 权限控制
- 只有超级管理员可以访问管理后台
- 部门管理员只能管理本部门用户
- 普通员工无法访问管理后台

## 7. 安全设计

### 7.1 权限控制
- 所有管理API需要超级管理员权限
- 部门管理员只能管理本部门用户
- 敏感操作需要二次确认

### 7.2 数据验证
- 输入数据验证（用户名长度、角色有效性等）
- SQL注入防护（使用SQLAlchemy ORM）
- XSS防护（前端输入过滤）

### 7.3 操作日志

## 9. 风险与应对

### 9.1 技术风险
- **数据库迁移**: 可能需要修改表结构
  - 应对：使用Alembic进行数据库迁移
- **性能问题**: 用户列表分页查询可能较慢
  - 应对：添加索引，优化查询

### 9.2 安全风险
- **权限提升**: 普通用户获取管理员权限
  - 应对：严格权限检查，API级别权限控制
- **数据泄露**: 用户信息泄露
  - 应对：数据脱敏，访问控制

### 9.3 用户体验风险
- **操作复杂**: 管理界面操作繁琐
  - 应对：简化操作流程，提供批量操作
- **响应慢**: 页面加载慢
  - 应对：前端优化，懒加载
