## 二、默认账号与权限体系

**第一个注册用户自动成为超级管理员**，后续注册用户默认为 `employee`。

管理员可通过管理后台分配角色和部门，无需手动修改数据库。

| `product_admin` | `admin123456` | dept_admin | 产品 |
| `product_emp` | `user123456` | employee | 产品 |
| `sales_admin` | `admin123456` | dept_admin | 销售 |
| `sales_emp` | `user123456` | employee | 销售 |

### 2. 三级角色与权限矩阵

| 操作 | super_admin | dept_admin | employee |
|------|-------------|------------|----------|
| 查看知识库 | 所有部门 + 公开库 | 本部门 + 公开库 | 本部门 + 公开库 |
| 用知识库问答 | ✅ | ✅ | ✅ |
| 创建/删除/编辑知识库 | 所有部门;可建**公开库** | 本部门(不能建公开库) | ❌ |

- **公开知识库**:创建时勾选"全公司可见",所有登录用户可见可用,仅超级管理员可管理;
- 权限在后端强制校验(`require_admin` 依赖 + 部门可见性),前端按钮只是体验层。

## 六、父子分块(检索优化)

系统采用**父子分块(Parent-Child Chunking)**策略提升检索质量,解决传统固定切块的矛盾(小块检索精准但上下文残缺,大块上下文完整但检索噪声多)。

### 原理

```
文档
 └─ 父块(大粒度,默认 2000 字)── 存 MySQL,不写入向量库,作为"完整上下文"
      └─ 子块(小粒度,默认 500 字)── 写入 Milvus 向量,作为"检索单元"
```

- **子块**:做 embedding + 检索(粒度小,命中精准)
- **父块**:检索命中子块后,映射回父块,把父块的完整文本交给 LLM(上下文连贯)

### 参数配置

创建知识库时配置三个切分参数:

| 参数 | 默认值 | 作用 |
|------|--------|------|
| 切块大小(子块) | 500 | 检索粒度,越小越精准 |
| 重叠大小 | 50 | 相邻块重叠字符数,避免切断关键句 |
| 父块大小 | 2000 | 上下文粒度,通常 ≥ 切块大小 × 4 |

### 检索流程

1. 用户提问 → 向量检索命中**子块**(Milvus 中的向量)
2. 子块 metadata 含 `parent_id` → 查 MySQL 对应**父块**
3. 父块去重(多个子块可能命中同一父块)→ 拼接为 LLM 上下文
4. LLM 基于父块的完整上下文生成回答

### 文档块管理

- **预览**:文档块列表仅显示父块(语义单位)
- **编辑**:编辑父块 → 自动删除旧子块 → 重新切分子块并重新向量化
- **删除**:删除父块 → 连同所有子块及向量一并删除

### 数据库结构

`chunks` 表的 `parent_id` 字段标识父子关系:
- `parent_id = NULL`:父块(有完整 content,无 milvus_id)
- `parent_id = N`:子块(指向父块 id,有 milvus_id)

## 八、对话问答与引用溯源

- **流式输出**:回答逐 token 渲染(SSE),支持多轮历史对话、温度/TopP/最大 token 可调;
- **引用溯源**:回答标注来源编号 [1][2],**点击编号可跳转到对应知识库详情并高亮定位到具体文档块**;
- **检索来源**:每条回答下方显示"🔍 检索:知识库A · 知识库B"(记录本次问答检索了哪些库,便于评测排查);
- **记住勾选**:对话页上次勾选的知识库会自动保存,下次进入自动恢复;
- 引用映射与检索来源均随消息**落库持久化**,查看历史对话依然可点击、可追溯。

## 九、日志

- 日志文件:`data/logs/app.log`(按 10MB 轮转,保留 5 份)
- Docker 部署:挂载 `./logs:/app/logs` 目录
- 同时输出到控制台,格式:`时间 | 级别 | 模块 | 消息`
- 日志级别由 `.env` 的 `LOG_LEVEL` 控制(默认 `INFO`,排查问题可设 `DEBUG`)

已记录的关键事件:用户注册/登录、知识库创建/删除、文档上传/解析(成功与失败)、问答检索与生成、检索失败告警、管理后台操作。

此外每个 HTTP 请求都会记录方法、路径、状态码与耗时(如 `GET /api/auth/captcha -> 200 (74.62ms)`),`/health` 已跳过避免刷屏。

```bash
# 实时查看后端日志
tail -f data/logs/app.log

# Docker 部署时查看后端日志
docker logs -f rag-backend

# 查看日志文件
ls -la logs/
```

## 十、常见问题排查

| 问题 | 排查方向 |
|------|---------|
| 后端启动报 MySQL 连接失败 | 确认 `docker compose up -d mysql` 已启动;核对 `.env` 的 DB_* 配置 |
| 注册/登录报"验证码错误" | 确认验证码输入正确、未过期(5 分钟);测试环境可设 `CAPTCHA_ENABLED=false` |
| 登录报"账号已被禁用" | 联系管理员启用账号,或检查 `users.is_active` 字段 |
| 文档上传解析失败 | 检查 `EMBEDDING_API_KEY` 是否有效;看文档 `status` 字段的 `error_msg` |
| 上传报"文件过大:最大支持 10MB" | 超过上传上限;改 `.env` 的 `MAX_UPLOAD_SIZE_MB` 并同步改前端 nginx `client_max_body_size`,重建后生效 |
| 上传一直报"网络错误" | nginx `client_max_body_size` 未生效/未重建镜像,413 被前端兜底为网络错误 |
| 上传文档一直卡住 | Docker 部署时后端连 Milvus 应用 `milvus:19530`(服务名),不是 `localhost`;并确认 milvus 容器与 backend 在同一 Docker 网络 |
| 问答无输出 | 检查 `LLM_API_KEY` 是否已填;看后端日志 |
| 检索不到内容 | 确认知识库已上传文档且状态为 `completed`;用 RAGAS 评测评估召回率 |
| 历史对话引用 [N] 不可点 | 该消息为旧版本生成(未持久化引用映射),重新提问即可;新版消息引用可点击 |
| 员工看不到知识库 | 检查该用户是否已分配部门(`users.department_id`);未分配部门仅可见公开库 |
| 前端请求 401 | token 过期,重新登录;检查 localStorage 是否存有 token |
| Docker 后端连不上 Milvus | 确认 milvus 容器在运行,且已接入 backend 的网络(见"上传卡住"条目) |
| 忘记 MySQL 密码 | 见第一节表格;或 `docker exec -it rag-mysql mysql -uroot -proot123456` |
| 管理后台 403 | 确认当前用户角色为 `super_admin`,其他角色无法访问 |
| Redis 连接失败 | 检查 `REDIS_URL` 配置;确认 Redis 容器已启动;验证码会降级到内存存储 |
| 接口返回 429 | 触发限频限制,登录 5次/分钟,注册 3次/分钟,稍后重试 |
| 数据库迁移失败 | 检查 `alembic` 目录是否存在;查看迁移日志;可设 `AUTO_CREATE_TABLES=true` 跳过迁移 |
