# 技术改进:问答引用溯源与历史追溯

> 日期:2026-08-24
> 涉及:检索元数据、SSE 协议、消息持久化、对话前端
> 对应需求:回答引用 [N] 可点击跳转文档块;历史对话可追溯检索来源

---

## 1. 变更概述

原系统回答中的来源编号 [1][2] 是**纯文本**,无法跳转;历史消息无法得知"当时检索了哪些知识库";
且存在一个隐藏 bug:混合检索的 **BM25 命中不带元数据**,导致这些子块从未被映射回父块。

本次实现**完整引用溯源链路**:

1. 修复 BM25 命中元数据缺失(父子映射、引用映射对 BM25 命中生效);
2. 回答中的 [N] 渲染为可点击链接,跳转知识库详情并**高亮定位到具体文档块**;
3. 引用映射随 SSE 下发并**落库持久化**,历史消息依然可点击;
4. 每条消息记录**检索的知识库来源**(`kb_ids`),便于评测排查;
5. 对话页**记住上次勾选**的知识库(localStorage)。

---

## 2. 新旧功能对比

| 场景 | 旧行为 | 新行为 |
|------|--------|--------|
| 回答中的 [1][2] | 纯文本 | **可点击链接**,跳转知识库详情 → 自动打开文档 → 滚动高亮到对应块 |
| BM25 命中的子块 | 无元数据,不映射父块(隐藏 bug) | 携带 kb_id/document_id/parent_id,正常映射父块 |
| 引用映射的存储 | 仅 SSE 一次性下发,前端内存持有 | **落库**(`chat_messages.citations`),历史消息/刷新后仍可点击 |
| 历史消息的检索来源 | 无 | 每条消息带 `kb_ids`,前端显示"🔍 检索:知识库A · 知识库B" |
| 对话页知识库勾选 | 每次进入都要重选 | localStorage **记住上次勾选**(与当前可见库求交集) |
| 旧消息兼容 | — | 无 citations/kb_ids 的消息退化为纯文本,不影响使用 |

## 4. 数据与接口变化

**表结构(新增列):**

| 表 | 列 | 说明 |
|----|-----|------|
| `chat_messages` | `citations` JSON | 引用映射 `[{index, kb_id, document_id, chunk_id}]` |
| `chat_messages` | `kb_ids` JSON | 本次问答检索的知识库 id 列表 |

**API 变化:**

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/chat/stream` | SSE 在 [DONE] 前新增 `data: {"citations": [...]}` 事件 |
| GET | `/api/chat/sessions/{id}/messages` | 消息响应新增 `citations` / `kb_ids` 字段 |

---

## 5. 影响与注意事项

- **历史消息**:仅修复后生成的消息有 citations/kb_ids;修复前消息退化为纯文本(不受影响);
- **链接准确性**:引用编号对应"上下文顺序",与 LLM 引用一致;旧数据(无 parent_id 的扁平块)退化为文档级链接(不带块定位);
- **XSS 安全**:[N] 用组件渲染而非 `v-html`,LLM 输出不可信;
- **评测价值**:消息级 `kb_ids + citations + content` 构成可复现的最小单元,可对接 RAGAS 或人工排查"答错库/漏库"。
