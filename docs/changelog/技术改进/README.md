# 技术改进文档

> **约定**:每次修改代码后,在 `docs/技术改进/` 下新增一篇对比文档,记录**旧行为 vs 新行为**、改动点、影响与验证情况。
>
> 命名:`YYYY-MM-DD-主题.md`(一次较大的功能/修复一篇;小修改可并入当日文档)。
>
> 早期问题修复汇总见 [`docs/Bug修复历程.md`](../Bug修复历程.md)。

## 文档模板

每篇文档建议包含以下章节:

1. **变更概述** —— 一句话说明改了什么问题/加了什么能力,以及动机;
2. **新旧功能对比** —— 按场景列出"旧行为 vs 新行为"表格,是文档核心;
3. **代码改动点** —— 文件级清单 + 关键函数/逻辑说明;
4. **数据与接口变化** —— 表结构变更、API 变更(新增/改签名/加字段);
5. **影响与注意事项** —— 兼容性、取舍、已知限制;
6. **验证情况** —— 测试结果、实测记录。
