# 技术改进:上传链路健壮性(大小限制、doc_count 计数、进度重置)

> 日期:2026-08-24
> 涉及:nginx 配置、后端上传校验、文档计数、解析进度
> 对应问题:大文件上传报"网络错误";知识库文档数恒为 0;同名重传进度读到遗留值

---

## 1. 变更概述

上传链路存在三处问题,本次一并修复/增强:

1. **上传无大小限制**:nginx 默认 `client_max_body_size=1MB`,超限直接 413(HTML,无错误信息),前端兜底显示"网络错误";
2. **文档计数只减不加**:`doc_count` 仅在删除时 -1,上传从未 +1,知识库列表"文档数"恒为 0;
3. **重传进度残留**:同名重传时进度接口会先读到上一次解析遗留的 `completed`,前端提前显示"解析完成"。

---

## 2. 新旧功能对比

| 场景 | 旧行为 | 新行为 |
|------|--------|--------|
| 上传 >1MB 文件 | nginx 413 HTML → 前端"网络错误" | nginx 上限 10MB;后端二次校验,超限返回明确提示"文件过大:最大支持 10MB" |
| 无 Content-Length 的请求 | 无防护 | 流式分块计数兜底,超限中断并清理残留文件 |
| 上传文档后列表计数 | 恒为 0 | `doc_count` 上传 +1 / 删除 -1,与 documents 表一致(存量数据已回填) |
| 同名重传后查进度 | 可能读到上次遗留 completed | 上传时重置进度为 0,仅 pending 才启动解析 |
| 前端提示 | 无大小说明 | 上传弹窗提示"单个文件最大 10MB" |

---

## 3. 代码改动点

| 文件 | 改动 |
|------|------|
| `frontend/nginx.conf` | 新增 `client_max_body_size 10m;`(曾设 100MB,按需求改为 10MB) |
| `config/settings.py` | 新增 `max_upload_size_mb = 10` |
| `app/services/document_service.py` | 上传流式写入时计数 + 计算文件哈希;超限抛 413 并清理;`doc_count += 1`;上传时 `_set_progress(id, 0)` |
| `app/api/document.py` | 仅 `status == "pending"` 才启动解析 |
| `frontend/src/views/KnowledgeBaseDetail.vue` | 上传弹窗提示大小上限 |
| `.env.example` | 新增 `MAX_UPLOAD_SIZE_MB` |

---

## 4. 数据与接口变化

- 无表结构变化;
- `.env` 新增配置 `MAX_UPLOAD_SIZE_MB`(默认 10),需与前端 nginx `client_max_body_size` 保持一致;
- 上传接口新增 413 语义:超限返回 `{"detail": "文件过大:最大支持 10MB"}`。

---

## 5. 影响与注意事项

- 修改上限需**两处同步**(nginx + `.env`),并重建镜像;
- 存量知识库的 `doc_count` 已通过 SQL 回填为实际文档数;
- 10MB 为传输上限而非推荐值:大文档解析耗 embedding 额度与时间。

---

## 6. 验证情况

- 实测:>10MB 上传返回 413 明确报错,≤10MB 正常;
- 回填后各知识库 `doc_count` 与 documents 实际行数一致;
- 全量 pytest 通过。
